# 项目生命周期与连续性协议

## 1. 信息读取顺序

每次开始任务时按顺序读取：
1. 项目管理数据库中的项目记录。
2. 该项目所有未完成任务，以及最近完成的相关任务。
3. 最近一次交接记录、目标变更和关键决定。
4. 仓库 README、开发说明、项目状态快照和相关模块文档。
5. Git 分支、工作区差异、最近提交、Issue / PR 和测试状态。

如果某一来源不可访问，明确标注缺失，不以其他来源的旧摘要冒充实时状态。

## 2. 任务生命周期

推荐状态：
- 待开始：尚未执行。
- 进行中：正在执行。
- 等待审批：需要用户对方案或关键操作作决定。
- 遇到阻碍：依赖、环境或技术问题导致无法继续。
- 已完成：完成标准全部满足并有证据。
- 已取消：用户明确取消，保留原因和历史。

若当前数据库没有某个状态选项，使用最接近的可用状态，并在任务正文写明真实子状态；不要擅自声称数据库已经支持该状态。

## 3. 任务追加与优先级

新任务进入时：
- 搜索是否已有相同或高度相似任务。
- 若是同一任务的补充要求，更新原任务并保留变更历史。
- 若是独立任务，追加新任务并关联项目。
- 若它改变已有任务的范围，记录变更原因和影响。
- 任务排序可以变化，任务本身不能因排序变化而消失。

优先级建议：
- 高：阻塞关键路径、安全风险、用户明确要求优先、关键验收。
- 中：当前阶段必要但不阻塞其他工作。
- 低：体验优化、可选增强、未来想法。

不要仅因新增高优先级任务就删除或自动取消其他任务。

## 4. 目标版本管理

使用目标版本而非覆盖历史：
- G0：初始目标。
- G1、G2：每次被确认的目标修订。

每次修订记录：
- 日期和提出者。
- 修订前目标。
- 修订后目标。
- 修订原因与依据。
- 对现有代码、任务、时间、成本和风险的影响。
- 用户确认状态。
- 生效日期。

未经确认的重大调整只作为提案存在。

## 5. 交接协议

交接至少包含：
- 项目和仓库。
- 当前目标与当前任务。
- 已完成的工作和证据。
- 未完成任务及其优先级。
- 当前阻塞、待审批和未知事项。
- 修改过的文件、分支、提交。
- 实际执行过的命令和测试结果。
- 下一步的准确操作。
- 不要重复做的事情和需要保留的用户修改。

交接应能让另一个 Agent 在不重新询问用户、不重复已完成工作的情况下继续。

## 6. 进度口径

可报告：
- 任务状态数量。
- 已验收的里程碑。
- 已交付功能与测试覆盖情况。
- 当前阻塞和风险。
- 距离下一里程碑还差哪些可验证事项。

不可报告：
- 无分母的完成百分比。
- 仅根据代码量估计的完成度。
- 将规划完成、代码完成、测试完成和发布完成混为一谈。

## 7. Notion 与仓库的职责

- Notion：跨项目的目标、任务、优先级、决定、进度和交接入口。
- Git 仓库：代码、配置、技术文档、Skill 源文件、提交和 PR。
- 测试结果：功能验收证据。

本地状态文件是快照或技术交接材料，不应成为与 Notion 并行、互相矛盾的任务系统。
